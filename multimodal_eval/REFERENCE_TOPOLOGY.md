# 独立图样的拓扑参考约定

本约定用于新的真实或许可公开样本，在首次视觉调用前独立标注和核对。校验器
`multimodal_eval/reference_topology.py` 只检查参考中的节点、杆件、交汇几何与完整性；
不读取模型预测、不调用运行时拓扑检测，不写入连接答案或修正原参考。
本轮没有新增在线调用或独立图样成绩，合成回归只验证约定和调用边界。

标注顺序：先按 EXIF 纠正、裁剪及旋转后的图片标注节点与杆件，再逐对检查杆件。
坐标 point 是 [u, v]，分别归一化到 [0, 1]；像素换算用 width_px−1 和 height_px−1。
节点和杆件编号须唯一，杆件必须引用已有节点且非零长。重复杆件、共线重叠会拒绝，
应在调用前人工明确几何，必要时使用能区分重叠杆件的其他视图。

每个实际相交的杆件对只留一条 intersections 记录：

| 情况 | decision | node_id | 核对重点 |
| --- | --- | --- | --- |
| 两杆件引用同一端节点 | connect | 该共享节点 | 包括共线接头，不可因看起来没有交叉而漏标 |
| T 端点接触或 X 内部相交，图中明确连接 | connect | 参考中位于交点的节点 | 从原图确认连接证据，不按静定性猜测 |
| 图中相交但明确不连接 | cross | null | 保留交点位置，不创建连接节点 |
| 证据无法确定是否连接 | 尚未完成参考 | 尚未完成参考 | 保持 pending，不进入新的在线验收 |
| 两段不相交 | 无记录 | 无记录 | 不把延长线相交或靠近端点当成线段交点 |

三根杆件在同一节点汇合，要记录三对；四根汇合要记录六对。交点 ID 及杆件对各自唯一，
成员顺序不影响判断。位置与参考线段交点及连接节点相差最多 1 px，用于人工坐标舍入；
这是参考内部一致性检查，原预测匹配容差、评分规则及验收阈值没有改变。

新模板中的两处标记示例：

```json
{
  "reference_contract": "space-frame-reference-topology/v1"
}
```

上面属于 metadata；下面属于 ground_truth。复核前 status 保持 pending，几何和交汇
都完成后才能改为 verified。校验通过只表示内部完整，不能证明人工连接判断正确，
也不意味着得到外部专家复核或自动识别准确。

```json
{
  "topology_reference": {
    "format": "space-frame-reference-topology/v1",
    "scope": "all_member_pairs",
    "status": "pending"
  },
  "intersections": [
    {"id": "joint-1-2", "members": [1, 2], "point": [0.5, 0.5],
     "decision": "connect", "node_id": 3}
  ]
}
```

运行 init 只生成缺失模板，不覆盖旧文件。status 的 topology_reference.errors 列出
漏标、重复、错位、悬空引用或未确认决定等原因；校验不自动修改参考。新的 recognize
即使没有模板版本标记，也必须通过完整参考检查，才会创建客户端和发送图片。
响应记录调用前参考哈希；调用中或调用后改标注会导致 response_ground_truth_mismatch，
缺少必要绑定会导致 response_ground_truth_unbound，freeze 会拒绝，已有响应不会重跑。

旧冻结目录及历史报告保持原字节。未满足新约定的旧样本仍可评分/回放，但报告列出
reference_contract.legacy_cases，说明旧拓扑参考或调用前哈希未验证，不视为新独立验收。
后续发现缺项时保留旧失败，另外建立调用前标注的新轮次；用于改算法的图片不再作为
新的独立验证。运行时现已记录引用同一节点的共线接头，端点参数按节点编号确定；
重叠仍阻断，仅坐标重合而编号不同的共线端点不自动连接。这类图样仍须人工核对。
旧参考缺少接头时，新回放可能增加未匹配预测；保留旧失败，不删交点或放宽评分。

再次 freeze 只核对并返回已经冻结的 manifest，不补新版本字段或重写换行/排版。
已冻结目录不接受增减图片，元数据变化也会拒绝；需要新样本或新输入时另建轮次。
