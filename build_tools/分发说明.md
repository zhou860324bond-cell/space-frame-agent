# 打包与分发

## 给要打包的人（你）

在项目根目录双击 **`build_exe.bat`**。

- 第一次打包**请先跑 `build_exe.bat --debug`**：它打出的版本保留控制台窗口。
  打包体第一次启动八成会缺某个动态导入的模块，无控制台版只会一闪而过，
  什么都看不到；带控制台的能把 traceback 留在屏幕上。
- 构建要 5~15 分钟，别关窗口。
- 产物是 `dist\FrameLab\`，**整个文件夹**才是程序，单独拿 `FrameLab.exe` 跑不起来。
- 分发就把这个文件夹压缩成 zip。

### 体积

600 MB ~ 1 GB，压缩后 250~400 MB。这不是打包没做好，是三个大件砍不掉：

| 组成 | 干什么 | 能不能去掉 |
|---|---|---|
| VTK | 画三维云图 | 不能，那是这个软件的核心 |
| Qt (PySide6) | 整个界面 | 不能 |
| gmsh | 节点实体子模型的四面体网格 | 能，但会丢掉应力集中那一整块功能 |

已经砍掉的：streamlit、plotly、pyarrow、tornado（网页版那条路径，桌面端用不到，
这几个加起来上百兆）、pytest、tkinter、其他 Qt 绑定。

### 为什么是文件夹不是单文件

单文件版每次启动都要把近 1 GB 解压到临时目录，VTK 冷启动 30~60 秒——
用户会以为程序卡死然后强退。文件夹版首次 3~5 秒，之后更快。

### 密钥安全

`deepseek.key` **不会**被打进去，`frame_lab.spec` 里有一道断言专门拦这个，
真收进去了会让构建直接失败而不是打出一个带密钥的包；`build_exe.bat`
构建完还会再扫一遍 `dist\FrameLab\`。

打包前请再自己确认一次：**把密钥打进分发包，等于把你的 API 额度送给每个拿到
文件的人。**

### 许可

PySide6 / Qt 是 LGPLv3。分发这个打包体需要随包附上 LGPL 声明，
并且不得阻止使用者替换其中的 Qt 库。`dist\FrameLab\` 是动态链接的
文件夹结构，天然满足后一条；前一条把本文件和各依赖的 LICENSE 一并放进
zip 即可。

## 给拿到 zip 的人

1. 解压到任意目录（**路径不要带空格以外的怪字符**，建议全英文路径）。
2. 双击 `FrameLab.exe`。
3. 首次启动 3~5 秒，出现窗口即可用。

### 常见问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 双击没反应 / 一闪而过 | 杀软拦了未签名的 exe | 在杀软里放行整个文件夹 |
| 提示缺 `VCRUNTIME140.dll` | 缺 VC++ 运行库 | 装微软官方的 VC++ Redistributable (x64) |
| 窗口是黑的 / 三维视口不显示 | 显卡驱动太老，OpenGL 起不来 | 更新显卡驱动 |
| AI 对话说"未配置 API 密钥" | 没放密钥，属正常 | 见下 |

**离线也能用。** 建模、求解、云图、强度验算、报告全部是本地确定性计算，
不需要联网也不需要密钥。只有"用中文跟它说话"那部分要接大语言模型。

要用 AI 对话的话：在 **`FrameLab.exe` 旁边**新建一个纯文本文件
`deepseek.key`，里面只写你自己的 API key 一行，存成 UTF-8，重开程序即可。
**不要用别人给的 key**，那是在花别人的钱。
