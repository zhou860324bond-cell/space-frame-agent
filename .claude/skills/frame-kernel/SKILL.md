# 空间刚架内核编码约定

这里的错误大多**不报错**：结果看着合理，只是差了 1000 倍、四倍或符号反了。
下面每一条都对应仓库里真实出过的问题。动手前先读涉及模块的文件头文档字符串，
那里记录了该模块自己的坑。

## 1. 坐标与符号（不可改动，只能遵守）

- 每节点 6 个自由度，顺序 `(ux, uy, uz, rx, ry, rz)`，`frame3d.DOF_PER_NODE`、
  `frame3d.LOCAL_DOF_NAMES`。不要在别处重新写一遍顺序。
- 局部轴一律调用 `frame3d.local_axes(pi, pj, ref)`，不自己求：局部 x 沿 i→j；
  局部 y 由参考向量投影，默认全局 +Z（水平杆件"向上"）；**竖直杆件参考向量退化，
  改用全局 +X**。这是空间刚架最经典的 bug 来源。
- 强轴约定：局部 y 朝上，平面内弯曲绕局部 z。高 h 宽 b 的矩形 `Iz = b·h³/12`
  是强轴。搞反挠度差一个数量级（见 `sections.py` 文件头）。
- 截面内力取 **j 侧部分作用在截面上的合力**，x=L 处等于杆端力 `f[6..11]`，
  x=0 处等于 `-f[0..5]`；轴力受拉为正。推导写在 `internal_forces.py` 文件头。
  悬臂自由端弯矩必须归零——新写任何内力恢复都先拿它验。
- 杆端释放通过静力凝聚实现（`_condense`）；半刚性连接是把 `K_rr` 换成
  `K_rr + k_s`，铰和刚接是它的两个极限。不要另写一套"铰接单元"。
- 峰值取绝对值最大且**并列取第一个**：用 `internal_forces.peak_index` /
  `exceeds`，不要直接 `np.argmax(np.abs(...))`——对称结构的最不利位置会随末位
  舍入跳动。

## 2. 单位制

- 内核量纲无关：N-m-Pa 与 N-mm-MPa 两套都支持，**求解过程不做任何换算**，
  模型数值一个字节不动。混用（m 配 MPa）不支持也检不出。
- 与单位制有关的只有两处：重力加速度和显示换算。一律从 `units.of(model)`
  取（`units.py` 文件头），**禁止**在代码里写 `9.81`、`9.80665`、`/1e6`、`*1000`。
  - 真实事故：`strength.py` 曾把应力硬编码 `/1e6` 当 MPa，毫米制下 150 MPa
    报成 0.0 MPa；反应谱曾默认 g=9.81，毫米制下地震作用小 1000 倍。
- 报给用户/Agent 的数用固定显示单位：位移 mm、力 kN、弯矩 kN·m、应力 MPa。
- **任何阈值都必须与单位制无关**。比较前先无量纲化：
  - 刚度类量先做对称 Jacobi 缩放 `D = diag(1/√Kᵢᵢ)` 再判条件数或主元
    （`frame3d.solve`、`silent_failures.check_near_singular_stiffness`）。
    真实事故：同一榀框架 SI 下条件数 6.5e3、毫米制下 7.1e8，被误报"接近奇异"。
  - 长度、位移用结构特征尺寸归一；力用总外荷载归一。
  - 写阈值时问自己：把模型换成另一套单位，这个判断还成立吗？

## 3. 物理杆件 vs 分析单元

- 用户操作的是**物理杆件**（Domain IR 的 `members`），求解器消费的是**分析单元**
  （`frame3d.Member`）。两者的唯一权威映射是
  `model_compiler.compile_model(payload).mapping`（`CompilationMap`）：
  `mapping.element_ids(physical_id)`、`mapping.physical_member_id(element_id)`。
  GUI、Agent、求解器都只消费这一份，不要自己按坐标或 ID 去猜。
- 凡是涉及**整根杆件**的量——长度、计算长度、欧拉临界力、沿杆内力图、挠度、
  逐杆校核——都必须经过映射按物理杆件算（参照 `strength._member_view`、
  `internal_forces.physical_member_diagram`）。
  - 真实事故：被两等分的杆拿分段长度算 Pcr，临界力变成四倍，偏不安全且不报错。
- 拿不到 mapping 时可以退化为"每个单元当一根杆"，但必须在返回的 `notes`
  里写明，不能静默。
- 物理杆件首末端结果不平均；跨分析段连续恢复内力与挠度。

## 4. 结果从 Result DB 读

- 结果层次固定为 `ResultDB → Step → Frame → FieldOutput`（`result_db.py`），
  每个字段带位置、坐标系、单位、平均规则。查询、绘图、报告三者同源。
- 新增结果量时**先在 Result DB 里定义字段及其元数据**，再让各消费方读；不要在
  绘图或报告里各自从 `Solution` 重新推导一遍语义。
- 不连续量（单元应力、杆端内力）默认不跨单元平均；显示裁剪不改变报告的真实峰值。

## 5. 信息不够就拒绝，不估算

- 缺几何、缺材料参数、超出适用范围时，抛模块自己的异常（`StressUnavailable`、
  `StrengthUnavailable`、`CompilationError`、`SolidJointError` 等），**绝不估算**。
  "一个来路不明的数比没有数更危险。"
- 异常消息写给用户和 Agent 看：点名实体（杆件/节点编号）、说明原因、给出下一步
  （补哪个参数、调哪个工具、换哪个后端）。
- 推定值与用户给定值要区分：推出来的数在输出里标来源（如 `mu_source`）并附警告。
- 公式有适用范围的（欧拉公式只在比例极限内、线性屈曲是上限、P-Δ 是小应变），
  要在代码里判断范围，并在输出里写明限制，不要只写在注释里。

## 6. 长任务与取消

- 循环里的增量步、迭代、网格档、样本点之间调用 `task_control.checkpoint()`，
  响应用户停止。矩阵分解等不可中断步骤之后再检查。
- 内核不 import Qt，也不做线程管理；后台调度由 `desktop/` 的任务运行器负责。

## 7. 测试要求

新数值功能至少有下面三类中适用的全部：

1. **闭合解对照**：真值来自经典理论、静力平衡或闭合特征值，**不来自本项目另一份
   实现**；容差按数值精度给（参照 `docs/BETA_0.1_GOLD_CASES.md` 已用的
   `1e-9`~`1e-11`），**不得为通过测试放宽阈值**。能进金标准的同步登记。
2. **单位不变性**：同一模型存成 N-m-Pa 与 N-mm-MPa，工具输出逐个数字相同。
   新工具加进 `tests/test_unit_invariance.py` 的现有模式里，不要另起炉灶。
3. **收敛方向**：涉及离散的（一致质量阵、几何刚度阵、实体网格），验证加密时
   单调逼近，且偏差方向符合理论（一致质量与一致几何刚度从上方逼近）。

另外：

- 测试文档字符串写清它防的是哪个真实问题（AGENTS.md 的约定）。
- 修 bug 先写能复现的失败测试，确认旧代码红、新代码绿。
- 只跑相关测试时用 `python -m pytest tests/test_xxx.py`；收工前 `python -m ruff check .`。
