# Agent 后续重点方案（2026-10-14）

本文是下一阶段建议，不代表已经实现的新功能。本轮实际实现仅为结果明细独立窗口。

## 已有基础

当前Session注册63个确定性工具，模型、结果和工具记录统一保存在会话中；
Conversation具备多轮调用、上下文裁剪、取消及部分常用指令的本地快速路径。
删除与批量修改已有预演和确认约束，桌面与Agent共用模型及撤销历史。
已有工具返回校验、求解、结果查询及分析限制；模型路由记录实际调用与耗时。
这些能力应直接复用，避免新建一套模型状态或只依赖提示词约束。

## 方案一：任务驱动的工程助手（推荐先做）

用户提出任务后，先提取已知条件和缺失条件，生成可执行的阶段清单：
几何、属性、边界与荷载、校验、求解、结果解释、导出。
由任务状态管理器记录阶段、模型指纹、实际工具调用和未完成事项，
AI助手显示当前阶段、下一步和需要用户补充的内容。

例：用户要求两跨框架求最大位移，尺寸已给、截面未给。
先建立合法几何草稿，明确只询问缺失截面；补充后继续原任务，避免从头重建。
网络失败、取消或达到调用上限时，显示已经完成的操作及下一步，按当前模型重新核对后恢复。
已有危险变更确认流程继续使用；并不把每个普通工具调用都变成确认步骤。

主要新增：任务状态、缺失条件表、阶段执行与恢复、桌面任务卡。
主要风险：任务状态与人工编辑不同步，恢复时重复提交修改或混入过期结果。
验收：多轮补参、人工插入修改、取消与恢复、失败重试均有真实工具记录；
未提供材料/荷载时不自行补数，已完成且模型未变的阶段不重复执行。

## 方案二：模型审核与结果解释助手

围绕当前模型回答为什么不能计算、载荷是否正确传递、控制工况与控制位置在哪里。
串联现有校验、机构诊断、平衡检查、静默失败检测和结果查询，
将问题定位到真实节点/杆件，按原因、证据、处理建议展示。
用户认可的修复再通过已有结构化变更工具应用并复验。

例：求解得到零位移时，先区分无荷载、传力断开、约束或结果失效，
引用工具返回的不可用标记及下一步建议，不能仅因为求解成功就宣布模型正确。
局部实体应力解释保留网格、截取范围和切面反力限制，不自动宣称收敛或安全。

主要新增：诊断工作流、证据引用、可点击问题定位、修复前后复验。
主要风险：把警告等同于失败，把自洽性等同于正确性，或误把不完整强度检查当规范验算。
验收：每条工程结论能追到模型版本、工况、工具调用与字段，所有不可用和限制均保留。

## 方案三：参数方案比较助手

用户明确变量、候选范围和评价目标，Agent在隔离模型副本中生成、计算与比较多个方案；
沿用现有截面优化和查询工具，输出质量、最大位移、控制内力/验算项及适用限制。
保留原模型，选择某一候选后再预演应用差异。

例：比较用户给出的三种梁截面，在同一几何、材料、荷载和支座下查看质量与位移变化。
不得自行假定可用截面、目标限值或连接刚度，也不把最轻候选直接称为工程最优。

主要新增：候选模型隔离、任务预算、对比表、结果存档与选定方案应用。
主要风险：改变多个输入后仍宣称只比较截面、候选失败被遗漏，或大量计算超出预算。
验收：同一基线、各候选实际求解记录、失败与未判定候选均显示，原模型在用户选定前不改变。

## 建议顺序

先做方案一的小范围闭环：规则框架分阶段建模、缺参补充、求解及最大位移查询。
随后加入方案二的审核与证据解释，提高已有工具的可信度与可用性。
最后在隔离模型和可追溯结果稳定后加入方案三。
评测沿用固定案例，并新增未参与开发的任务；分别记录任务完成、误改模型、数值溯源、
失败恢复、模型往返次数与实际耗时。评测结果以真实运行记录为准，不在本计划里预填指标。
