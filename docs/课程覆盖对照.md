| 七 | **支座沉陷问题**（转化为装配内力） | ✅ | agent 工具 `set_prescribed_displacement` |

**关于第三条**：项目原有 `buckling_analysis`，做的是**整体特征值屈曲**
`(K + λK_g)φ = 0`——理论上比欧拉公式高一档。但讲义要的是**逐杆的欧拉校核**，
两者不是一回事：前者回答「整体什么时候失稳」，后者回答「这一根会不会先屈」。
**有更高级的方法不等于覆盖了讲授内容**，所以 `strength.py` 把逐杆欧拉校核
按讲义原样补齐了，两条路径都在，可以互相核对。

## 缺口清单与建议

按**答辩风险**排序，不是按工作量。

### 1. ~~强度验算（§3-9 三）~~ —— 已完成 2026-09-10

`src/strength.py`。讲义把这一条拆成强度与稳定两件事，两件都做了。

**强度**：逐杆取最不利截面的极端纤维正应力，**拉、压分别对各自的许用值**。
材料加 `allow_tension` / `allow_compression`；只给拉的按钢材惯例取同值，
但会在输出里写明「压许用未给，取拉许用」——是默认就得让人看见。

**稳定**：受压杆逐根按 `Pcr = π²EI/(μl)²` 校核，输出回转半径 `i=√(I/A)`、
长细比 `λ=μl/i`、两个主轴各自的 `Pcr` 并取小者。μ 可以在杆件上直接给
（`mu_y`/`mu_z`），不给则按讲义的四种端部约束推定。

三处刻意做成「宁可拒绝也不猜」：

- **μ 的来源分得清清楚楚**。由杆端释放只能推出**无侧移**情形的 μ，
  推定值一律标 `mu_source: 由杆端释放推定` 并附警告：有侧移的框架柱 μ>1，
  推定值偏小 → Pcr 偏大 → 判定偏不安全。悬臂柱（μ=2.0）从杆端释放根本看不出
  （自由端是节点没约束，不是杆端释放），必须显式给。
- **欧拉公式的适用范围**。σcr = π²E/λ² 只在比例极限内成立。给了
  `yield_stress` 就判 λ 与 λp = π√(E/σs)；λ<λp 时直接判**不通过**并说明原因，
  而不是拿一个超过屈服应力的 σcr 判「稳定够」。没给 `yield_stress` 就明说
  「无法判断适用范围」，不假装通过。
- **剖分**。杆件被自动剖分后若按分段长度算 Pcr，两等分就是**四倍**——
  偏大、不报错、看着还合理。所以传了编译映射时一律按**物理构件整根**算；
  没传映射会在 `notes` 里写明「结果偏不安全」。

验证：`tests/test_strength.py` 15 项，判据全是闭式解。做过两次变异检验：
把拉压合成 `|σ|/[σ]`、把欧拉长度换成分段长度，各自都会立刻失败。

| 算例 | 真值 |
|---|---|
| 轴力杆 | `σ = N/A`，应力比 `= σ/[σ]`，逐位相等 |
| ft=40MPa / fc=120MPa，σ=60MPa | 受拉 1.5 超限、受压 0.5 通过 |
| 两端铰支压杆 | `Pcr = π²EI/L²`，`λ = L/√(I/A)` |
| 同一根柱剖成两段 | `Pcr` 与整根**逐位相同** |
| 粗短杆 + σs=235MPa | `λ<λp` → 判不通过，且此时 `N/Pcr < 1`（正是会误判的情形）|
| 换到 N-mm-MPa | 应力比与稳定比逐位相同 |

**答辩时要说清的边界**：这里只有正应力，没有剪应力与扭转（截面契约里没有
一次矩和壁厚，见 `stress.py` 的说明），所以不是规范意义上的构件承载力验算；
逐杆欧拉校核回答「这一根会不会先屈」，`buckling.py` 的特征值屈曲回答
「整体什么时候失稳」，两者不能互相替代。

### 2. ~~装配内力 + 温度应力（§3-9 五、六）~~ —— 已完成 2026-09-10

按讲义"转化为装配内力问题"的思路做成**一条**路径：两者都只是给杆件一个初应变
ε₀，转成沿杆轴的等效节点力 `EA·ε₀` 进右端项，回算内力时再减掉。

三条设计决定：

- **存应变，不存 Δl / ΔT**。应变沿杆是常量，杆件被自动剖分时各段直接继承，
  剖分逻辑完全不需要知道长度。
- `lack_of_fit` 定义为「实际长度 − 设计长度」，**正值 = 做长了**，与升温同向。
  这样两种输入的符号含义一致，不用记两套规则。
- 材料没给 `alpha` 就算温度应力会被**拒绝**，而不是默默按 α=0 算出
  「没有温度应力」——后者是最糟的失败方式。

验证：`tests/test_initial_strain.py` 13 项，全是闭式解，不是回归快照。

| 算例 | 真值 |
|---|---|
| 两端固定 + 升温 | 位移恒零，`N = −EA·α·ΔT` |
| 一端自由 + 升温 | `N = 0`，自由伸长 `α·ΔT·L` |
| 降温 | 号相反，受拉 |
| 两端固定 + 装配误差 | `N = EA·Δl/L`，换杆长必须跟着变 |
| 温度 vs 等效装配误差 | 两条输入逐位相同 |
| 与外荷载叠加 | 分开算再相加 = 一次算完 |

**最容易错的是「一端自由 + 升温」那条**：回算内力时若忘了把初应变减掉，
自由伸长的杆会凭空出现 `EA·α·ΔT` 的轴力，而方程照样有解、不报任何错。
做过变异检验：去掉那一项、或把符号写反，都会立刻失败。

顺带补了三处容易漏的：删杆件时清理它的初应变、换单位制时 `lack_of_fit`
按长度换算而 `delta_t` 不换、剖分后各段继承。这三处漏掉都不报错。

### 3. ~~带宽优化编号 + 等带宽带状存储 + 总刚一维存储（§3-9 八、§3-10、§4-6）~~
—— 已完成 2026-09-10

做成**教学对照路径**，不替换主求解器：

    frame3d.solve(model)                        ← 稀疏 LU（默认，主链路不变）
    frame3d.solve(model, factorize=factory())   ← 一维变带宽 LDLᵀ（skyline.py）

两条路径**共用同一份装配、约束消元、沉降处理与反力回算，只有分解这一步不同**。
这是刻意的：否则比出来的差异分不清是解法的还是装配的。

`src/skyline.py`——一维变带宽存储（Bathe 的 COLSOL 约定，也就是讲义的 A 与 MAXA）：

    a[maxa[j] + k] = K[j-k, j]      k = 0 … 列高_j

对称只存上三角，按列存到该列最高的非零元为止；列高不必相等，这就是「变带宽」
相对「等带宽」的全部区别。配套 LDLᵀ 分解与前代/回代，即讲义 §4-6 的那几个子函数。
不做主元交换——对称正定不需要，**遇到非正主元直接抛异常**，因为那意味着约束
不足或存在机构，安静地算下去只会得到一个看不出问题的错误答案。

`src/numbering.py`——节点编号（§3-9 八）：节点号差 `max|j−i|`、按节点号估计的
半带宽 `6(j−i)+6`、矩阵的实际半带宽、变带宽存储量，以及**自己写的 RCM**
（BFS + 层内按度数排序 + 整体反转，二十来行）。在随机图上与 SciPy 的实现对比过，
不比它差。

**一条刻意的约束：不改用户的节点号。** 节点号是用户和大模型在对话里一直引用的
东西（「3 号节点加个铰」），求解器擅自换掉，用户后面每一句话都会对错人。所以
重编号只发生在求解内部：排列作用在自由度上，右端项进来先排、解出来再排回去，
模型本身一个字节不动。有测试专门盯这一条。

**数据**（`tools/skyline_bench.py` 生成，完整表在 `docs/带宽存储对比.md`）：

| 算例 | 自由度 n | 半带宽(原→RCM) | 满阵 n² | 等带宽 n·b | 变带宽(原→RCM) | 稀疏非零 |
|---|---:|---:|---:|---:|---:|---:|
| 4跨10层×2进深 | 600 | 65→65 | 360,000 | 39,000 | 34,646→31,625 | 19,440 |
| 同上（打乱编号） | 600 | **563→65** | 360,000 | 39,000 | **124,509→31,625** | 19,440 |

这张表要说三件事：

1. **变带宽比满阵省一个量级**（34,646 / 360,000 ≈ 9.6%），这是讲义要讲它的原因。
2. **编号真的值钱**。同一个结构、同一个答案，只把节点号对调一遍，半带宽从 65
   涨到 563（8.7 倍），变带宽存储量从 3.5 万涨到 12.5 万（3.9 倍）。RCM 把两者
   都拉回原值——这正是讲义 §3-9 八那条判据的价值。
3. **但稀疏存储更省，也更快**：稀疏非零 19,440，只有变带宽的 56%，耗时也只有
   一半左右（600 自由度：103 ms vs 214 ms）。**变带宽的额外开销全在「列内的零
   也要存」**。所以现代求解器换掉这套方案不是因为讲义讲错了，而是因为按行列
   索引直接存非零元、再配合填充最小化排序，比「用带宽把非零元圈起来」更彻底。
   讲义的方案在没有稀疏矩阵库的年代是**唯一可行**的做法，理解它才能理解稀疏
   求解器在解决什么问题。

验证：`tests/test_skyline.py` 22 项。核心判据只有一句——换了存储和解法，
**位移、反力、杆端力必须一致**（相对差 1e-14 量级）。只对位移是不够的：反力和
杆端力是解出位移之后再算的，装配或消元哪里被动了手脚，它们才会露出来。
MAXA 指针、列高、存储量都用手算的 4×4 例子钉住；奇异矩阵必须抛异常而不是返回
垃圾；打乱编号后答案不变而存储量变，RCM 能拉回来。

### 4. 对称性的利用（§3-9 四）——可以论证不做

现代做法通常直接算全模型，对称性主要是手算时代节省工作量的手段。

但**必须在报告里明确写出来「为什么不做」**，不能装作讲义里没有这一条。
如果时间允许，做一个「对称性检测 + 提示」也够交代——检测出结构对称就告诉
用户「本结构关于 X 平面对称，可用半结构校核」。
