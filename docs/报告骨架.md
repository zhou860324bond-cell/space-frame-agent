## 1 选题背景与意义（C，600 字）

**要点**

- 结构分析软件的门槛不在算法，在前处理：建模、约束、荷载、单位，每一步都要人工。
- 大模型能读懂"三跨六米两层"这种自由表述，但**不能让它算数**——这是本项目的出发点。
- 一句话立论：**把大模型放在它不可替代的位置（意图理解、诊断解释），
  其余全部交给确定性代码。**

**别写**：泛泛的"AI 赋能"。评委见得太多，且和后面章节接不上。

## 3 系统架构与技术路线（A + B，1200 字 + 1 张架构图）

**要点**

- 三层：求解内核 / Agent 层 / 评测与验证
- **Schema 作枢纽**：`MODEL_SCHEMA` 是唯一契约，大模型只产它，不产数值
- 数据流图（照抄 `README.md` 里那张，补成正式图）：

```
自然语言 → LLM → JSON 模型 → validate_payload()
                                ├─ 有错 → 中文错误清单回喂重试
                                └─ 通过 → solve() → check_equilibrium()
                                                 → diagnose_singularity()
```

**三条设计原则**（这是全文的骨，务必写透）：

1. 大模型只产结构，不产数值 —— 回答"你怎么知道它没在编"
2. 拓扑由代码展开 —— 多层多跨让模型列坐标必然出错
3. 算前守门 —— 且**必须独立于求解是否报错**（理由见 6.2 第四条）

## 4 关键技术（A + B，2500 字）

### 4.1 空间梁单元与求解内核（A，1000 字）

> 现已支持：规整框架、坡屋面门式刚架、增量原语（加节点/加杆件/删杆件）、
> 按尺寸算截面特性、Abaqus 可选求解后端。写的时候按最终代码核对，别照抄骨架。


- 12×12 局部刚度矩阵、坐标变换、稀疏装配
- **杆端释放的静力凝聚**：按 `f_released = 0` 缩并，等效荷载同步处理，
  求解后用凝聚关系还原被释放自由度的真实位移
- **多工况只分解一次**：`splu` 一次分解、逐工况回代；组合按线性叠加，不重算
- 代码：`src/frame3d.py`（约 700 行）

### 4.2 参数化生成器（B，500 字）

- **意图 → 参数 → 拓扑** 的分工点。这是本项目的一个技术贡献，单独成小节。
- 论证：让模型逐个列节点坐标，多层多跨必然数错、漏杆；
  改为 `generate_frame(spans, storeys, bays, ...)`，节点编号与连接由代码展开
- 数据：三跨两层单开间 → 24 节点 36 杆件，与手算一致
- 代码：`src/generator.py`

### 4.3 Agent 层与工具设计（B，700 字）

- 9 个工具，按工程意图切分（表格照抄 `README.md`）
- **工具返回的错误信息质量，决定 Agent 好不好用**——这一条有实测支撑，见 6.1
- 逃生舱设计：规则结构走 `generate_frame`，不规则结构走 `set_model`

### 4.4 算前守门与自修复闭环（B，300 字 + 1 张演示截图）

- 两级校验：JSON Schema 查结构 → `check_model` 查语义，错误清单为中文，可直接回喂
- 奇异诊断：对约束后刚度阵做特征分解，取近零特征值向量映射回节点自由度
- **这是全项目最扣题的一处**：纯数值方法给不出建议，纯大模型给不出零空间
- 图：`examples/agent_demo.py` 的输出截图（失败 → 诊断 → 修复 → 重算）

### 5.2 与 Abaqus 对标（A，1000 字 + 2 表）

- **单元选择要写清楚**：主对标用 **B33**（Abaqus 的 Euler-Bernoulli 梁，
  与本程序同一套理论），B31 作对照
- 误差定义：`e_X = sqrt(Σ(X_本−X_abq)²) / sqrt(Σ X_abq²)`，逐分量算
- 五个算例：见 `abaqus_bench/README.md`
- **前两例故意用强弱轴悬殊的截面**（`Iy`∶`Iz` = 1∶20），
  一旦 `I11/I22` 映射搞反，误差从 1e-6 跳到百分级——这是拿实验验证假设，值得写
- 数据源：`abaqus_bench/benchmark_B33.md`、`benchmark_B31.md`（**已跑出**）

**B33 结果**（十个作业全部 `ANALYSIS COMPLETED SUCCESSFULLY`，0 error 0 warning）：

| 算例 | 节点 | 本程序 / Abaqus (mm) | e(\|U\|) |
|---|---:|---|---:|
| 悬臂强轴 | 9 | 42.8571 / 42.8570 | 8.7e-06 |
| 悬臂弱轴 | 9 | 857.1429 / 857.1000 | 5.3e-05 |
| 扭转杆 | 2 | 纯扭转 | ur1 = 4.2e-06 |
| 门式刚架 | 7 | 6.3901 / 6.3901 | 7.2e-06 |
| 空间刚架 | 18 | 0.6771 / 0.6771 | 5.8e-06 |

反力误差到 **1.6e-13**（真正的机器精度）；位移那 1e-5 的量级来自 `.dat` 只打印
五位有效数字，不是真实差异——这一点要在文中说明，否则读者会以为是误差下限。

**B31 那组 2026-09-16 查清了：是离散误差**（此前两次改口——先写成"格式差异"，
2026-09-11 复核后改为"待查项"，现在有实验结论了）：

| 算例 | 本程序 / B31 (mm) | 方向 |
|---|---|---|
| 悬臂强轴 | 42.8571 / 43.1080 | Abaqus 偏软 0.59% |
| 悬臂弱轴 | 857.1429 / 856.3000 | Abaqus 偏硬 0.10% |
| 门式刚架 | 6.3901 / 5.6073 | Abaqus 偏硬 12.2% |
| 空间刚架 | 0.6771 / 0.6489 | Abaqus 偏硬 4.2% |

只有第一例符合"多一项剪切柔度所以更软"。后三例 Abaqus 更硬，剪切变形
解释不了——**多一项柔度不可能让结构变刚**。

> 原稿在这里写的是"偏差随细长比单调排队、B31 更软"，**与自己的表格矛盾**：
> 按 L/r 排是 18.4→6.68e-03、31.6→1.53e-01、88.2→3.47e-02，根本不单调——
> 这条观察当时是对的，它排除了"细长度补偿"这个方向。
>
> **2026-09-16 查清**：主因是离散误差。B31 是线性单元而我们一根杆一个单元，
> 加密到 8 段后各分量单调收敛到本程序的值。当时怀疑的横向剪切刚度已用实验
> 排除（显式加到 1e12，Y 向响应仍是零）。正文 5.3 节与
> `abaqus_bench/B31收敛性.md` 有完整记录。

### 5.3 Agent 评测集（B，900 字 + 2 表）

- 14 题六类：规则框架 3、信息不全 3、解析解 3、多工况 2、机构诊断 2、单位换算 1

## 6 结果与讨论（C，2000 字）

**这一章是拉开差距的地方。** 前面各节都是"我们做了什么"，这一章是"我们发现了什么"。

### 6.1 评测集迭代：设计判据比调模型难（1000 字 + 3 份报告对比）

三轮演进：86% → 86% → 100%，但**六道失败题全部是评判标准的问题，
没有一道是模型的问题**：

| 轮次 | 题 | 判据错在哪 | 模型实际做了什么 |
|---|---|---|---|
| 1 | C02 | 判据挂在模型自定的组合名上 | 正常建了 3 工况 2 组合 |
| 1 | M02 | 要求求解失败 | 自诊断后修复成功 |
| 2 | Q03 | 拿问号当追问的判据 | 用陈述句列出了缺失项 |
| 2 | M02 | 要求"必须先失败" | 预先避开了陷阱 |

**结论**：给 Agent 设计评判标准，比调 Agent 本身难。三次都栽在同一个陷阱上——
把"我以为的正确路径"当成唯一正确路径。

**同时要写风险**：不能一路放宽到全部通过，那就成了对着答案改卷子。
本项目的做法是**换一个更有意义的判据**而不是降低要求（Q03 那条同时收紧了
另一个方向：泛泛而谈也不再算追问）。

数据源：`evalset/report_run1.md`、`report_run2.md`、`report_run3.md`
（`report.md` 始终是**最近一次**成绩，会被重跑覆盖；三轮演进那一轮
另存为 `report_run3.md`，免得叙事的第三个数据点被下一次重跑抹掉）

### 6.2 四个技术发现（700 字）

每条写成"现象 → 根因 → 处理 → 一般性教训"：

1. **局部坐标系参考向量退化**：竖直杆件默认参考向量与杆轴平行，须特判
2. **内力回算漏加固端力**：支座弯矩对、跨中弯矩全错，错得不明显
3. **轴力取错分量**：以拉为正的是 `f[6]` 不是 `f[0]`，两者符号相反。
   **纯看数字时藏了很久，画成轴力图当场露馅**（柱子被画成受拉）
   → 教训：可视化不只是展示手段，是一种独立的校验方式
4. **`splu` 遇奇异不一定报错**：荷载不激发那个刚体方向时，它会安静返回一个
   看似合理、连平衡校核都能过的错误位移场
   → 教训：**算前守门必须独立于"求解是否报错"**，不能指望求解器替你发现建模错误

### 6.3 成本与可复现性（300 字）

- 实测：14 题 × 3 轮 = 953 秒，输入 863959（缓存命中 88.9%），输出 117408，
  合计约 0.71 元
- **反直觉的一点**：输出只占 token 总量 12%，却贡献七成以上成本
- 可复现性：工具描述一改就等于提示词变了，`temperature=0` 也保证不了跨版本复现。
  本项目用**源码指纹**把结果与代码版本绑定

**结论**：三条设计原则 + 三层验证，做出一个数值可溯源、行为可评测的空间刚架 Agent。

**不足要写足，别藏**（评委一定会问，主动写反而加分）：

- 求解范围限于各向同性线弹性、小变形、线性静力

# 答辩三问

准备到能脱口而出，三个人各自答自己那块。

**一、你怎么知道算出来是对的？**
三层验证。解析解到机器精度、Abaqus 对标、评测集三轮记录波动范围
（13/14 ~ 14/14，**不是零波动**，见 5.4 与上面那条）。
补一句：**评分器本身也有测试守着**。

**二、为什么必须用大模型？确定性代码不也能做？**
答案在 4.4。奇异诊断这一处，纯数值方法能算出零空间但给不出人话建议，
纯大模型能说人话但算不出零空间——**只有两者结合才有**。
另一处是信息不全时主动追问，脚本只会套默认值算下去。

**三、和 Abaqus 的差异从哪来？**
B33 同为 Euler-Bernoulli、一个单元即精确，误差是数值精度量级，梁单元验证
以这组为准。B31 那组 2026-09-16 查清了：**主因是离散误差不是格式差异**——
B31 是线性单元而我们一根杆只划一个单元，加密到 8 段后单调收敛到我们的值。
截面朝向、横向剪切刚度、摄动步三个假设都做实验排除了（见 `B31收敛性.md`）。
**这条比原先那句"格式差异"强得多：加密之后 B31 自己收敛到了我们这一侧，
等于它反过来印证了我们的解。**
